# Pajero Gen 1 inclinometer — ESP32-S3 2.8" round display

Firmware for the **Waveshare ESP32-S3-Touch-LCD-2.8C** (480×480 round ST7701 RGB panel, QMI8658 IMU) that mimics the
Mitsubishi Pajero Gen 1 dash inclinometer (blue/orange face, see `images.jpeg`).

- **Roll (side tilt):** the whole face rotates about the centre. That's the blue/grey halves, the orange horizon
  line and the vertical pitch scale. Read where the horizon meets the outer ring. Each end of the horizon points at
  its own scale. The upper (black) half has 10/20/30/40 and the lower (grey) half has 5/15/25/35/45. For example,
  15° to the right shows as the left end of the horizon at **15** on the lower scale (`0120.jpg`).
- **Pitch (fore/aft):** the red-orange domed **needle** slides along the vertical scale. Read the number at the
  needle. At level it sits on the horizon. Nose up moves it toward the black numbers (`0121.jpg`: 20). Nose down
  moves it toward the orange numbers (`0122.jpg`: 15).
- The motion is spring-damped so it moves like the fluid-filled original. Like the original, it is only exact when
  the vehicle is stationary.

## Build & flash

Requires [PlatformIO](https://platformio.org/). The pinned pioarduino platform (Arduino core 3.3 / ESP-IDF 5.5) downloads automatically.

```bash
pio run -t upload
```

```bash
pio device monitor
```

The serial monitor prints the mapped accelerometer reading, the angles and the frame rate 5 times a second.

## Flashing a prebuilt .bin (no PlatformIO)

Ready-made images are attached to each GitHub **Release** (`v1`, …). [`firmware/README.md`](firmware/README.md) explains them. A release carries `firmware.factory.bin` and `firmware.bin` from `.pio/build/inclinometer/`, renamed:

| File | Flash at | Use |
|---|---|---|
| `inclinometer-full-0x0.bin` | `0x0` | Complete image (bootloader + partition table + app) for a blank or foreign board. It also **erases the saved level**, so send `z` or long-press afterwards. |
| `inclinometer-app-0x10000.bin` | `0x10000` | App only, for updating a board that already runs this firmware. It keeps the saved level. |

```bash
esptool.py --chip esp32s3 write_flash 0x0 inclinometer-full-0x0.bin
```

Browser flashers such as the Espressif web flasher take the full image at offset `0x0`. If the port doesn't show
up, hold BOOT, tap RESET, release BOOT.

## "Set level" button

No touch input is used. Calibration uses **GPIO0**:

- the on-board **BOOT** button works as-is, or
- wire an external momentary push button between **IO0** and **GND** on the 12-pin header (in parallel with BOOT).

Park on level ground and **hold the button for 2 s**. The display shows *KEEP HOLDING*, then *HOLD STILL* while it
averages for 1 s, then *LEVEL SET* with a beep. If the vehicle moved, it shows *TRY AGAIN*. The reference (mounting
rotation and gyro bias) is stored in flash and survives power cycles.

Without a button, use the serial monitor instead: send `z` to set level (same as the long press) or `c` to clear
the stored reference.

Don't hold the button while powering up or pressing reset, because that puts the ESP32 into download mode.

## Mounting

Mount the screen upright, facing the driver, so the screen is roughly perpendicular to the direction of travel.
Calibration absorbs small mounting tilts and any rotation of the IMU chip within the board plane.

`include/config.h` already maps this board's IMU axes. On the 2.8C, the chip's X axis points up the screen and its
Z axis points into it. If the ball moves the wrong way on a different board revision, edit it and rebuild:

- `ROLL_SIGN` / `PITCH_SIGN`: flip to `-1.0f` if roll or pitch is reversed.
- `IMU_MAP_X/Y/Z`: remap or negate the chip axes. With the board standing upright and screen facing you, the serial
  monitor should show `acc` ≈ `+0 +1 +0`. Tilting the top away from you should make Z go positive.

Other tunables in `config.h` include damping (`NEEDLE_OMEGA`), filter time constant, backlight, buzzer, and the
display pixel clock.

## Project layout

| Path | Purpose |
|---|---|
| `src/gauge.*` | Dial renderer. It pre-renders the ring and ball texture at boot, then each frame rotates the face and pitch scale by roll, slides the needle along the scale by pitch, and adds spherical shading. |
| `src/canvas.*` | Small anti-aliased rasterizer used for pre-rendering |
| `src/font_data.h` | Baked anti-aliased glyphs (generated by `tools/gen_font.py`, Liberation Sans Bold) |
| `src/display.*` | ST7701 init (Waveshare sequence) and an `esp_lcd` RGB panel with two PSRAM framebuffers swapped on vsync |
| `src/expander.*` | TCA9554 IO expander (LCD reset/CS, buzzer) |
| `src/imu.*` | QMI8658 register driver |
| `src/attitude.*` | Complementary filter, level calibration (NVS), damping spring |
| `src/button.*` | Debounced long-press button |
| `tools/sim/run.sh` | Builds the renderer on the PC and writes PNG previews of several poses to `tools/sim/out/` |

## Previewing without hardware

```bash
tools/sim/run.sh
```

This renders the level pose, the three reference photo poses, an extreme tilt and a message overlay into
`tools/sim/out/sheet.png`.
